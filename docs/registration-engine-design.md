# 원본 보존형 문항 등록 엔진 설계

작성: 2026-09-18. 이 문서는 **구현된 기준선**, **권장 설계**, **미검증 가설**을 구분한다. 현재 웹 UI를 전면 교체하지 않았다. 실험 결과는 `output/registration-baseline/`에 있으며 원본 PDF와 파생 이미지는 비공개 로컬 자료로 취급한다.

## 1. 문제 정의와 보존 정보

목표는 전사가 아니라 재사용 가능한 원본 영역과 관계의 복원이다. 비용 최적화의 분모는 검출된 상자 수가 아니라, 원래 존재한 모든 문항 중 수업에 실제 사용할 수 있는 문항 수다. 필기 제거와 문항 분리는 별도 작업이다.

원본 바이트, SHA-256, 페이지 수·MediaBox/CropBox·회전·좌표 단위, 원본 파일 참조, 렌더링 버전·주석 정책, 분석 변환, 각 조각의 읽기 순서, 원본 번호와 섹션, 공통 자료와 의존 관계, 관계별 근거·확정 여부를 보존한다. 누락된 원문을 생성하지 않는다. 표·수식·도형·답안란·의도된 여백도 내용이다.

실제 사례: 지정된 PDF는 22,482,714바이트, 7쪽. PDF.js 구조 점검에서 모든 페이지의 텍스트 항목 및 별도 주석은 0개였다. 회전 메타데이터는 90/270도가 섞였다. 렌더링 육안 점검에서 표지와 2단 수학 문제지, 원본 이미지에 합쳐진 필기·채점 표시를 확인했다. 파일명이나 학교명은 알고리즘 입력 특징으로 사용하지 않는다. 국어·영어 장문 공통 지문 성능을 이 파일로 검증할 수 없다.

## 2. 권장 데이터 모델과 관계

`SourceDocument(id, ownerScope, sha256, originalAssetId, mime, pageCount, pageFrames, versions)`와 `AnalysisRun(id, sourceId, engineVersion, modelHashes, configuration, stages, budgetLedger)`를 추가한다. 페이지 프레임은 PDF 기본 사용자 공간(통상 pt, UserUnit 별도), CropBox, 회전, 분석 픽셀 크기 및 변환을 갖는다.

`Fragment`는 단일 페이지의 다각형이다. 축 정렬 사각형뿐 아니라 원근 보정 후 역변환된 사각형의 네 꼭짓점을 저장한다. `sourceToAnalysis`와 역행렬은 3×3 동차좌표 행렬로 보존하고 왕복 오차를 검증한다. 원근 이외의 비선형 펼침을 도입하면 행렬만으로 부족하므로 버전 있는 변위망과 역매핑을 추가한다. 정보가 없는 변형은 금지한다.

`Question(id UUID, originalLabel, sectionId, orderedFragmentIds, requiredMaterialIds, parentId, childIds, dependencyIds, state, reasons, qualityAxes)`; `SharedMaterial`도 독립 UUID와 순서 있는 조각·필요 자료 ID를 갖는다. 원본 번호는 표시값이다. 문항에 포함되는 선택지 묶음은 별도 choice 노드로 표현할 수 있다.

관계 테이블: `continues(fragment→fragment)`, `belongs_to(fragment→question/material)`, `choice_of(choice→question)`, `requires_material(question/material→material)`, `child_of(question→question)`, `depends_on(question→question)`. 각 관계에 `candidate/confirmed/rejected`, 근거 영역·텍스트 범위·방법·분석 버전·검토자를 둔다. 확정 관계를 정본으로 삼고 노드의 required/parent/dependency 목록은 트랜잭션 내에서 파생한다. 후보 관계는 파생 목록에 넣지 않는다.

예: 지문 M1=[p2:F1,p3:F2,p4:F3], 보조 표 M2=[p4:F4], Q11=[p4:F5], Q12=[p4:F6,p5:F7]. Q11→M1, Q12→M1, Q12→M2, M2→M1을 표현할 수 있다. Q12가 Q11의 답을 필요로 한다면 별도 Q12→Q11 의존 관계다. 번호 범위만 관측되면 이 간선들은 후보이며 자동 확정하지 않는다.

저장: IndexedDB 새 버전에 documents/fragments/materials/relations/analysisRuns 추가. 원본 Blob 한 번 저장, 고해상도 crop은 재생성 가능한 캐시. Exam snapshot은 확정된 그래프 버전과 원본 자산 참조를 고정한다. 원본 문제 삭제 시 참조가 남은 자산은 회수하지 않는다. 삭제는 참조 검사와 같은 트랜잭션에서 처리하고 crash 후에도 복구 가능해야 한다. 기존 단일 이미지 문제는 하나의 fragment로 호환하되 과거 PDF 원본을 보유했다고 꾸미지 않는다.

## 3. 전체 알고리즘

`입력 점검 → 페이지/영역별 구조 신뢰성 평가 → 물리 블록 후보 → 구역별 읽기 DAG → 문항/자료 가설 그래프 → 불확실성별 추가 인식 → 완전성 검증 → 필요한 부분 확인 → 버전 고정 저장`

A–G 단방향 한 번 실행보다 **증거가 누적되는 작업 큐**를 권장한다. 번호 인식이 바뀌면 영향받는 구역과 관계만 재평가한다. 단계별 결과를 저장하여 모델 실패로 이미 분석한 페이지를 잃지 않는다. 모호한 블록에 가능한 소속을 몇 개 남기고 비용·위험 우선순위로 처리한다. 모든 페이지를 처음부터 OCR하지 않되, 스캔 문서처럼 대부분 인식이 필요하면 배치 OCR을 선택할 수 있다.

## 4. 단계별 입력·출력·판단 규칙·실패 조건

| 단계 | 입력 → 출력 | 실행 규칙 | 실패/다음 행동 |
|---|---|---|---|
| A 점검 | 원본 → 페이지 프레임·텍스트·이미지/벡터/주석 목록·역할 후보 | 파일 시그니처·암호·크기·페이지·총 픽셀 예산 확인. 텍스트 정상 유니코드 비율, 중복 레이어, 좌표 범위, 렌더 잉크와 겹침, 샘플 OCR 일치도를 함께 평가 | 텍스트가 있어도 좌표 불일치면 해당 영역만 저신뢰. 암호/손상은 사유 표시. 첫 페이지 표지 가정 금지 |
| B 물리 후보 | 구조+분석 래스터 → 줄·문단·표·그림·단·전폭 블록 | 적응 이진화, 연결 요소 크기 분포, 수평/수직 잉크 투영, morphology, 선 길이/교차점 사용. 서로 다른 커널 크기로 후보를 유지 | 번짐·필기로 블록 합쳐짐, 분수/첨자가 떨어짐. 원본은 변경하지 않고 병합/분할 대안 유지 |
| C 순서/시작 | 블록+스타일 → 읽기 DAG·번호 후보 | 세로 구간별 단 구조 추정. 전폭 블록 전후에서 단 구역을 나눔. 같은 단 내 위→아래, 전폭 앵커 전후 precedence. 표기+들여쓰기+스타일+주변 본문+번호열+섹션을 함께 평가 | ①, (1), 식 번호는 부정 특징. 번호 재시작은 섹션 가설, 누락 번호를 생성하지 않음. DAG 충돌은 보류 |
| D 연결 | 순서+열린 상태 → 문항/자료/선택지 연결 후보 | 열린 지문/문항/선택지/하위문항/미배정 도형/남은 참조 범위를 문서 전체에서 유지. 문장·선택지 연속, 상자 경계, 번호 범위, 명시 참조를 조합 | 페이지 종료만으로 닫지 않음. 번호 없는 머리말을 앞 문항에 확정 연결하지 않음. 누락 페이지 의심은 incomplete |
| E 추가 인식 | 불확실성 큐 → 새 증거 | 번호/참조 줄 OCR → 레이아웃 → 텍스트 관계 모델 → 멀티모달 중 기대 수정시간 절감 대비 비용이 좋은 수단 선택 | OCR 자체가 AI. 작은 crop 반복 호출보다 구역/페이지 배치가 유리한지 실측. 실패/시간 초과 시 보존 후 review |
| F 제한 AI | 영역 ID+대안+문맥 → 구조화된 판단 제안 | ID/열거값/근거 참조 검증. abstain, revise_regions, missing_source 허용 | 알 수 없는 ID·순환·스키마 오류는 거절. 모델 자기신뢰를 정답 확률로 사용하지 않음 |
| G 검증 | 가설 그래프+원본 → ready/review/incomplete | 핵심 잉크/객체 경계 교차, 선택지 누락, 중복 소유, 인접 내용 혼입, 자료 폐쇄성, 읽기/연속 사이클, 미배정 핵심 블록 검사 | 경계·순서·자료·완전성 각각 결과를 남김. 예산 남으면 추가 분석, 아니면 검토; 불완전 문항 자동 출력 금지 |

초기 휴리스틱 임계값은 검증 데이터로 조정한다. 예를 들어 줄 높이 중앙값을 기준으로 형태학 커널·여백 허용폭을 잡고 픽셀 고정값을 피한다. 반복 머리말도 상단 위치, 여러 페이지 텍스트/모양 반복, 본문과의 구분을 함께 검사한다. 가로선은 분수선·표·답안란일 수 있으므로 삭제 규칙으로 사용하지 않는다. 영역 경계가 연결 요소를 가로지르면 안전 여백까지 확장하거나 후보를 재분할한다. 좌우 인접 문항과 겹치면 자동 확장 대신 검토한다.

문서 상태에는 최근 한 페이지만 넣지 않는다. 각 열린 노드의 요약, 최초/마지막 fragment, 미해결 참조를 유지하고, 처음에는 인접 구역, 다음에는 연결된 2·4·8쪽 범위, 마지막에는 문서 전체 인덱스로 문맥을 확장한다. 이미지 토큰 예산을 넘으면 전체를 축소해 읽히지 않게 보내지 말고 관련 조각 검색 또는 사람 검토로 전환한다.

## 5. 복잡한 유형별 처리 전략

- 혼합/불량 OCR PDF: 페이지뿐 아니라 영역별 native/OCR 선택. 숨겨진 OCR 레이어가 실제 잉크를 잘 설명하는지 샘플 비교. 벡터 윤곽 글자는 일반 텍스트 없는 것으로 처리하고 래스터 OCR 후보에 넣는다.
- 가변 다단/전폭 자료: XY-cut 단독 대신 세로 밴드별 투영·블록 정렬과 전폭 블록을 결합. 중앙선 없이도 열을 추정하고 선 하나로 확정하지 않는다. 필기 때문에 투영이 막히면 레이아웃 모델 후보를 비교한다.
- 회전/기울기/원근: PDF 회전부터 적용, 선/텍스트 기울기 분포로 deskew; 원근은 페이지 테두리 근거가 있을 때만. 불확실한 변형은 미적용. 원본과 정규화 미리보기를 왕복 가능하게 보존.
- 장문/여러 자료: 지문은 여러 fragment의 하나의 논리 노드. 하위 공통 자료는 별도 노드와 scope; 가까운 문항만 보고 연결하지 않는다. 문항 선택 시 material 의존 폐쇄만 자동 포함하고 관련 문항 전체를 강제 선택하지 않는다.
- 선택지/하위문항/번호 재시작: 선택지 묶음 상태를 열린 채 유지. 본문과 다음 단의 선택지는 서로 다른 조각이지만 같은 문항. 섹션 ID로 동일 번호 구분. 하위문항 parent 관계는 문항 시작 검출과 별도 처리.
- 표/그림/수식/답안 공간: 확인된 객체를 indivisible로 지정. 긴 본문만 검증된 문단 경계에서 fragment를 나눔. 빈칸·답안 표의 내부와 의도된 주변 여백은 보존한다. 미확인 긴 조각은 축소를 숨기지 않고 경계 확인을 요구한다.
- 누락/손상: 페이지 표기 연속성, 잘린 글자·상자, 미완성 선택지 및 명시 참조를 근거로 경고. 페이지 번호가 없으면 누락을 확정할 수 없음도 기록. 없는 자료는 생성하지 않는다.
- 표지/해설/답안지: 다중 단서로 role 후보화. 정답열·해설 문구와 문항 본문을 구분하되 전체 페이지를 조용히 버리지 않는다. 사용자가 제외를 되돌릴 수 있게 한다.
- 별도 주석: 포함/제외 렌더링을 비교하고 사용자가 선택. 원본은 불변. 합쳐진 필기는 색만으로 제거하지 않으며, 검정 필기와 인쇄 수식을 구별 못하면 원본 유지·검토 표시. 색상 약화는 분석 파생본에만 적용한다.
- HWP/HWPX: 원본 파일 + 변환 렌더/텍스트 + 변환기 버전·폰트 대체 경고를 저장하는 입력 어댑터로 공통 그래프에 연결. PDF 좌표라고 위장하지 않으며 기준 좌표는 해당 변환 페이지 프레임이다. 실제 HWP 재배치/누락 검증은 별도 필요.

출력은 원본 PDF clip 또는 고품질 crop을 렌더링하며 AI가 수식이나 도형을 재생성하지 않는다. 같은 출력 묶음 내 공통 자료는 버전 ID로 한 번 배치한다. 의존 문항이 선택되지 않으면 추가 필요 안내를 한다. 순서가 섞여 공통 자료의 맥락이 멀어지면 그룹 재정렬을 제안하되 조용히 순서를 바꾸지 않는다. 원본 번호는 보존하고 새 바깥 번호 옆에 `원문 12` 및 `새 번호↔원문 번호` 대응표를 둔다. `[11~13]`은 가리지 않고 '이 자료의 원문 번호 기준' 안내를 붙인다. 일부 문항만 선택해도 원본 표기를 변조하지 않는다.

검토 UI는 전체 썸네일+확인 필요 큐, 원본 위 오버레이, 연결된 다른 페이지 보기를 제공한다. 경계 조절/합치기/나누기/자료 지정/앞뒤 연결/자료 연결/제외를 같은 그래프 변경 명령으로 기록하고 undo 지원. ready는 자동 숨김이 아니라 빠르게 훑을 수 있게 유지. '모두 저장' 전 미완성은 제외 또는 미완성으로 보관을 명시적으로 선택한다.

## 6. AI 호출 조건과 형식

도입은 설계 단계이며 이 프로토타입은 외부 AI API를 연결하지 않았다. 다음 조건 중 하나가 있고 분석 예산이 남았을 때만 후보 작업을 만든다: 서로 다른 소속 가설 충돌, 자료 scope 불명, 다음 단 선택지 연결 불명, 물리 블록이 표/수식 경계를 가로지름, 누락 위험이 큰데 제한 OCR로 해소되지 않음. 문항이 명확하면 호출하지 않는다.

요청 예시(실제 모델 응답 아님):

```json
{
  "task": "resolve_relation",
  "schemaVersion": "1",
  "targetRegionId": "B17",
  "allowedRegionIds": ["B16", "B17", "B18"],
  "hypotheses": [
    {"kind": "continues", "targetId": "M1"},
    {"kind": "belongs_to", "targetId": "Q12"},
    {"kind": "new_material"}
  ],
  "context": {"openMaterialIds": ["M1"], "openQuestionIds": ["Q12"]},
  "evidence": {"textSpans": [], "overviewImageRefs": [], "cropImageRefs": []},
  "allowedActions": ["propose", "abstain", "revise_regions", "missing_source"]
}
```

응답 계약: `action`, `usedRegionIds[]`, `proposedRelations[{from,to,kind,evidenceRegionIds,evidenceTextSpans}]`, `reviewReasons[]`, `regionRevisionRequests[]`. 요청 ID allowlist, 관계 방향과 노드 타입, 근거 span 범위, 크기 제한을 JSON Schema와 그래프 검사로 검증한다. 좌표 수정 요청도 기존 영역 ID를 대상으로 하며 별도 분할 단계에서 실제 이미지와 대조한다. 자동 확정은 모델 말이 아니라 독립 검사와 검증 집합에서 정한 정책을 통과할 때만 허용한다.

문서 텍스트는 신뢰하지 않는 데이터로 구분한다. 문서 안의 명령은 실행하지 않는다. 모델에 도구 실행·파일 탐색·외부 URL 접근 권한을 주지 않는다. 원본에 없는 텍스트/수식/선택지/누락 페이지를 출력할 수 있는 필드를 만들지 않는다.

## 7. 비용과 상한

서비스 비용:

`C_service = CPU_core_seconds × CPU_rate + GPU_seconds × GPU_rate + API_input_units × input_rate + API_output_units × output_rate + storage_GB_month × storage_rate + I/O + egress`

단계 시간은 parse/render/CV/OCR/layout/relation/validation/retry로 분리한다. 각 단계의 CPU·GPU 비용에 이미 포함된 OCR을 다시 더하지 않는다. 재시도도 동일 stage ledger의 attempt별 실제 사용량을 합산하며 중복 항목으로 두 번 더하지 않는다. 브라우저 연산은 서버 청구에는 0일 수 있지만 사용자 기기의 CPU시간·메모리·전력·다운로드·지연은 별도 비용이다.

`T_review`는 활성 검토 초, 조작 횟수, 다시 연 문항 수로 측정하며 idle/background 시간을 분리한다. 선택적 환산 비용 `C_user = T_review_hours × assumed_hourly_value`를 보고할 수 있으나 서비스 청구와 혼동하지 않는다. 최적화 목적은 비용/지연/수정시간/중요 누락률의 Pareto 비교다. 문서 단위 실패도 분모에 남긴다.

**초기 정책 가정(성능 보장 아님):** 입력 50MB·40쪽, 누적 분석 이미지 100MP, 동시에 렌더링 1쪽·OCR worker 1개, 동일 미해결 영역 재분석 최대 2회, 외부 호출 문서당 최대 3회, 요청당 최대 4개 crop, 전체 외부 입력/출력 토큰 한도와 통화 예산을 배포 설정에서 필수 지정한다. 공급자 가격 또는 이미지 단위 계산이 설정되지 않으면 외부 호출을 비활성화한다. 작업 시간 목표 120초는 중단/재개 정책 평가용이며 현재 스캔 사례에 충분하다고 가정하지 않는다. 기준선 CLI는 40쪽 제한만 구현했고 나머지 비용 제어는 제품 구현 과제다.

호출 전 최대 비용을 예약하고 응답 사용량으로 정산한다. 재시도도 예약에 포함, 429/backoff는 상한과 deadline 내에서만 수행. 시간 초과가 실제 서버 작업 취소를 뜻하지 않으므로 provider request ID로 중복 청구/재시도 추적. 예산 소진 시 원본과 부분 결과 저장 후 검토로 전환한다.

캐시 키: 사용자 범위 + 원본 SHA-256 + 페이지/영역 + 분석 변환 + 주석 정책 + 엔진/모델 해시 + 옵션. 동일 원본 재처리는 정확 캐시, 비슷한 양식은 검증해야 하는 prior다. 학교명/고정 좌표 매칭은 금지한다. 다른 사용자의 비공개 자산을 hash 조회로 노출하지 않는다.

## 8. 비교 실험과 평가

아래 비용·지연·수정 부담은 **측정 전 가설**이다.

| 접근 | 유리한 입력 / 대표 실패 | 연산·API·지연 | 수정 부담 / 개발·유지보수 |
|---|---|---|---|
| A 구조+CV+선택 OCR | 정상 텍스트·일관된 단 / 필기·가변 단·불량 OCR·공통 자료 관계 | native는 가벼울 가능성, 스캔은 OCR 비용 증가. 외부 API 없어도 local 비용 존재 | 단순 문서 낮을 가능성, 복잡 문서 높음. 규칙 폭증 관리 필요 |
| B A+경량 layout | 표·그림·전폭 객체 / 새 양식·한국어 영역·문항 의미 연결 | 모델 초기화·메모리·CPU/GPU 추론 증가; 배치/상주 여부 영향 | 경계 수정 감소 가설. 모델 배포/버전/회귀 관리 추가 |
| C B+불확실 연결 multimodal | 장문·참조·다페이지 관계 / 나쁜 후보·잘린 원문·모델 환각 | 선택 호출 수·crop 크기·문맥 확장에 따라 변동, 긴 꼬리 지연 가능 | 관계 수정 감소 가설. 라우터·비용·스키마·검증 가장 복잡 |
| D 페이지 AI | 복잡한 페이지의 비교 기준 / 페이지 밖 관계·불명확 ID·누락 | 모든 페이지 전송/추론; 호출은 많아도 batching에 따라 C보다 효율적일 수 있음 | 전체 구조 빠른 실험 가능, 검증은 여전히 필요. 페이지 결과 연결 단계 공통 적용 |

동일 문서/렌더 품질/출력 스키마/검토 UI로 비교한다. D도 페이지 간 관계 평가에서 예외로 두지 않는다. warm/cold 모델, cache-hit/miss, 부분 OCR/page OCR을 분리하고 반복실행 p50/p95를 측정한다. 이번 1회 실행으로 지연 분포나 보편 비용을 주장하지 않는다.

라벨은 문항 시작/번호/섹션/필수 본문·선택지·표·그림 polygon/답안란/공통 자료/관계/순서/완전성. 둘 이상의 검토자가 모호한 경계·자료 의존을 독립 라벨하고 허용 대안과 불일치를 기록한다. 같은 출처·시험 시리즈·유사 양식·근접 중복은 같은 split에 둔다. 개발·검증·새 출처 holdout을 분리, 어려운 샘플은 제외하지 않는다. 권한 있는 스캔·native·혼합·필기·다국어·누락·장문 합성 자료를 층화한다.

지표: 문항 시작 precision/recall, 필수 영역 보존율과 critical omission 개수, 인접 내용 오염 면적/사건수, 관계 edge precision/recall, 순서 역전과 연속성 누락, 사용 가능한 문항/전체 원본 문항, 모든 필수 문항 완전한 문서/전체 문서, review 초/수정 횟수, 외부 호출·입출력 단위·재시도·저장 바이트·단계별 비용/시간. 경계 IoU만으로 성공 판정하지 않는다. 불완전 원본은 별도 분류하되 전체 분모와 계층별 결과를 모두 제공한다.

프로토타입 범위: 기존 segment 규칙을 재사용하는 A의 축소판. 영상 기반 전폭/가변 단 분석과 관계 의미 인식은 아직 없다. 모든 자동 관계는 candidate로 보존한다. 새 graph 모듈은 변환 왕복, 참조/일부 사이클, 자료 중복 제거, 누락 의존 및 후보 관계 차단을 검증한다. 합성 그래프 단위 테스트 통과는 실제 PDF 관계 정확도 증명이 아니다.

### 실제 실행 결과

원본/오버레이를 확인한 임시 라벨은 단답형 18 + 서술형 4 = 22문항이다. 인식 없는 기준선은 7쪽 전체를 미배정 상태로 보존했다. 로컬 OCR을 추가한 기존 규칙은 후보 4개를 만들었으나 표지 유의사항 3개와 5쪽 하단 필기 영역 1개를 잘못 검출했다. 실제 문항 시작점 22개를 모두 놓쳤고, 여러 페이지가 오인된 후보의 연속으로 묶였다. 이 파일의 수정 없는 사용 가능 결과는 **0/22**, 문서 성공은 **0/1**로 임시 육안 평가했다. 이중 라벨링한 정밀 정답셋 결과나 일반화 성능은 아니다.

로컬 OCR 실행은 외부 API 0회, 로컬 OCR 7회, 분석 wall 123.509초/프로세스 CPU 122.513초였다. 일부 다른 렌더 작업과 겹쳤으며 오버레이/HTML 쓰기는 시간에서 제외되어 통제된 end-to-end 벤치마크가 아니다. 금전 비용·사용자 수정시간은 미측정. 전처리 결과가 잘못되어도 조용히 승인하지 않고 모든 관계를 candidate로 저장했다. 상세 실패와 측정 파일은 `output/registration-baseline/findings.md`, `report-*.json`, `review-*.html`을 참고한다.

## 9. 최소 구현과 확장 순서

1. **현재 구현:** 읽기 전용 PDF 기준선 CLI, 원본 좌표/변환/조각/후보 관계 JSON, native-only와 local-OCR 실험, 페이지 오버레이 HTML, graph/reuse 단위 테스트. 원본은 주어진 경로를 참조한다. 경로 이동 후에도 유지되는 제품용 Blob 수명 관리와 UI 저장 연동은 아직 아님.
2. **가장 먼저 제품 반영:** 기존 `compose.ts`의 긴 PNG 합성·공백 trim을 기본 저장 방식에서 제거. IndexedDB graph 저장 및 Exam snapshot 마이그레이션, 조각 순서대로 배치하는 출력 렌더러, 후보 연결을 확인하는 검토 UX. 기존 이미지 문제 호환 유지.
3. **A 개선:** 유효 텍스트 평가, CV 구역/객체 후보, 번호 스타일과 섹션·서술형 표기, 자료 범위와 상태 기반 연결, 내용 보존 검증. 현재 파일의 필기/문항 시작 누락을 회귀 사례로 고정.
4. **B 실험:** PP-DocLayout-S를 서버/로컬 Python 선택 worker에 넣고 한국어·수식·필기 데이터로 측정. 프런트 전체를 모델 환경에 종속시키지 않음.
5. **C 실험:** 관계 작업 큐·API adapter·budget ledger·스키마 검사. 라벨 데이터로 자동 승인 조건 검증 후 제한 출시.
6. **D 비교 및 운영:** 동일 holdout·수정시간 기준으로 A/B/C/D 선택. 원본 제거 없는 cache GC, 작업 재개, 모델/룰 버전 회귀, 오류 triage. OCR 타이핑이나 필기 복원은 별도 기능.
