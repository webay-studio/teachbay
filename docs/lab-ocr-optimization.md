# PDF 영역 실험: 출력 보존 최적화

대상은 `/lab/pdf-regions`이다. OCR 모드·언어·해상도·패스 순서·번호 재시도 기준·영역 판정·지문 연결은 유지한다. `adaptive`로 기본값을 바꾸거나 확인된 문항이라는 이유로 다른 OCR 모드를 생략하지 않는다.

## 변경

- `lib/documents/ocr-result-cache.ts`: 실제 crop RGBA의 SHA-256, 가로/세로 크기, PSM, 숫자 whitelist, 엔진/언어 버전을 키로 OCR 결과를 재사용한다. 위치가 달라도 픽셀이 동일하면 같은 인식 결과를 사용할 수 있으며, 원본 페이지로의 좌표 변환은 각 요청에서 그대로 수행한다.
- `lib/documents/extract-experiment.ts`: 기존 패스 순서와 모든 관측을 유지한다. 캐시 hit에서도 현재 요청의 passId·관측 ID·원본 좌표를 새로 만든다. 오류·취소된 OCR은 저장하지 않는다. 결과는 실제 사용하는 글줄·단어·좌표·confidence만 보존한다.
- 캐시는 현재 탭 메모리에만 존재한다. 문자열 용량 추정 16MiB의 LRU 한도를 적용한다(전체 앱 heap 상한이 아니다). 새로고침/탭 종료 시 사라지고 IndexedDB·서버에는 저장하지 않는다. 픽셀이나 인식 옵션이 달라지면 OCR을 실행한다. 형태 분류만 변경했을 때 픽셀이 같으면 인식 결과만 재사용하고 후속 영역 판정은 재계산한다.
- `lib/documents/ink-regions.ts`: 각 픽셀 방문마다 생성했던 이웃 배열을 1회 생성한다. 글자 확장 기능을 사용하지 않을 때 동일 마스크를 다시 복사하는 순회를 제거한다. 연결 방식·필터 임계값·반환 순서는 그대로다.
- 화면에 실제 OCR 실행 횟수와 재사용 횟수를 구분한다. JSON의 기존 `ocrPasses`는 논리 패스 수로 유지하고 `ocrRecognitions`, `ocrCacheHits`, `ocrCacheMs`를 추가한다.

## 성능 해석

이 변경의 큰 효과는 같은 탭에서 같은 문서를 다시 분석할 때다. 처음 보는 문서는 기존 인식을 모두 수행한다. 첫 실행 속도가 대폭 빨라진다고 주장하지 않는다. 캐시 해시 계산과 조회 비용도 측정한다. 워커 병렬화나 고해상도 전체 페이지 버퍼는 이번에 도입하지 않았다.

## 검증

- `npm test`: 캐시 키 분리, LRU 용량, 변조 방지, 빈 OCR 결과 재사용을 포함한다.
- `npm run typecheck`, `TEACHWAY_BUILD_DIR=.next-optimized npm run build`.
- `LAB_BASE_URL=http://localhost:3037 node scripts/verify-lab-regions.mjs ocr-cache <PDF 경로>`: 같은 탭에서 최초 분석과 재분석을 실행한다. UUID와 측정 시간만 제외한 전체 JSON을 비교한다.
- `node scripts/compare-lab-results.mjs <기존 JSON> <새 JSON> <보고서 JSON>`: 군집·OCR 관측·문항 좌표·지문 연결·화면 그룹을 이전 결과와 비교한다.
- `output/region-regression/ocr-cache/components.json`: 국어 1·20쪽, 글자 확장 유무 및 4/8 연결의 8가지 경우에서 변경 전/후 컴포넌트 전체 배열이 동일했다. 단일 실행의 시간 수치로 일반적인 속도 향상률을 주장하지 않는다.

실제 브라우저 측정치는 `output/region-regression/ocr-cache/`에 저장한다. 원본 자료 및 인식 결과는 비공개 로컬 검증 파일이다.

- 기존 기준 결과 ↔ 최적화 최초 결과 ↔ 재분석 결과: 문항 번호, 본문/보조 조각 좌표·순서, 지문 연결 및 조각, 화면 그룹 좌표 모두 동일.
- 국어 fixture 최초/재분석 각각 323개 통과, 0개 실패.
- **원시 JSON 전체 동일성 검사는 실패했다.** 일부 렌더의 잉크 픽셀 수와 OCR 문자열·관측이 달랐다. 이를 숨기거나 최종 결과 일치와 혼동하지 않는다. OCR 0회인 디지털 수학 PDF에서도 반복 렌더의 잉크 데이터 차이가 관찰됐다. 동일 입력 픽셀인 요청만 재사용하며 차이가 있는 요청은 재인식했다. 정확한 렌더 차이 원인의 세부 분석은 이번 범위에 포함하지 않았다.
- 최초 분석 속도 개선, 모든 문서에서의 결과 동일성, 낙서 전처리 ON 상태의 전체 PDF 성능은 이 측정으로 입증되지 않는다.
