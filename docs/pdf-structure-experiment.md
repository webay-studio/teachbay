# PDF 문항 구조 실험 (미검증)

경로: `/lab/pdf-regions`. 기존 문제 등록 페이지에 별도 진입 링크를 추가했다. PDF만 입력하고, 영구 저장 없이 결과를 비교하는 페이지다.

## 실제 로직

- `lib/documents/extract-experiment.ts`: PDF.js로 페이지를 렌더링하고 PDF 텍스트 좌표를 얻는다. 동일 페이지 전체를 Tesseract kor+eng의 AUTO, SPARSE_TEXT 모드로 각각 읽는다. 기존 단 추정/번호 필터를 OCR 입력에 적용하지 않는다. 모든 인식 줄을 원본 좌표와 함께 유지한다. PDF 텍스트/OCR 중복도 목록에는 남긴다.
- `lib/documents/structure-experiment.ts`: 반복되는 가장자리 글자, 대상·조건, 수행 요구, 수식, 선택지, 공통 자료의 역할 단서를 부여한다. 문항 시작 후보는 번호만으로 확정하지 않고 주변 본문, 정렬 반복, 글자 높이를 함께 본다. 추출 후에 읽기 구역을 추정한다.
- 질문·수행 요구에서 앞쪽으로 인접 조건과 수식을 연결한다. 다음 번호까지는 탐색 범위이며 그 전체를 저장 범위로 삼지 않는다. 뒤의 선택지 후보를 추가한다. 연결 줄의 원본 바운딩 박스로 영역을 만든다.
- 시작을 찾지 못한 질문도 인접한 앞부분을 연결해 불완전 후보로 남긴다. 무소속 줄, 중복 후보, 원본을 버리지 않는다. 공통 자료 번호 범위와 이전 페이지 연결은 후보 관계만 출력한다.
- `app/lab/pdf-regions/page.tsx`: 원본 위의 글자/영역 레이어 전환, 문항 미리보기, 모든 글자 및 역할·이유 목록, JSON 다운로드. 기존 저장소/기존 분리 로직에는 적용하지 않는다.

## 구현의 한계

이번 버전의 역할 판단은 여러 언어·기하 단서를 결합한 규칙 기반 실험이다. 의미 이해 모델은 연결하지 않았다. 특정 종결어 하나로 문항을 확정하지 않지만, 인식 가능한 언어 패턴에 의존하므로 미지의 표현을 놓칠 수 있다. 역할 이름은 정답 라벨이 아니다.

OCR은 모든 글자를 읽는다는 보장이 없다. 수식은 잘못 읽을 수 있고 글자로 인식되지 않는 그림·표는 바운딩 박스 밖에 남을 수 있다. 이를 자동 포함하거나 복원했다고 표시하지 않는다. 필기 분류기는 없으며 필기도 구조 단서와 유사하면 포함될 수 있다. 복잡한 다단·문단 이어짐은 자동 확정하지 않는다. 페이지 간 후보는 제한된 탐색이며 의미상 연결을 보증하지 않는다.

사용자 요청에 따라 PDF 실행, 브라우저 테스트, 타입 검사, 린트, 빌드 등 검증은 실행하지 않았다. 성공률·처리 비용·정확도는 미측정이다.

## v2: 낙서 전처리 후 분석

`/lab/pdf-regions`에서 전처리는 기본 켜짐이다. PDF 원본을 먼저 Blob으로 보존한 뒤, 별도 분석 canvas에서 PDF 주석을 제외하고 빨강·파랑 계열 픽셀을 HSV 색상 규칙으로 흰색 처리한다. 이후 두 가지 전체 페이지 OCR과 기존 구조 연결 함수를 실행한다. 전처리 없이 다시 분석하는 옵션도 있다.

- 구현: `lib/documents/ink-preprocess.ts`의 `suppressColoredInk`.
- 어두운 픽셀(max RGB < 90) 및 저채도 픽셀은 유지한다. 주변 픽셀로 마스크를 확장하거나 가려진 원문을 생성하지 않는다.
- 제거 대상은 손글씨라고 판정된 영역이 아니라 색상 조건에 맞는 픽셀이다. 인쇄된 빨강·파랑 자료도 지워질 수 있고 검정 펜·연필·진한 겹침은 남을 수 있다.
- 주석 제외는 잉크 주석만이 아니라 모든 PDF 주석을 대상으로 한다. 필요한 설명이 주석에 있으면 전처리를 끄고 다시 분석해야 한다.
- 원본 자산과 전처리 자산은 동일 좌표·해상도로 별도 보존한다. 원본/전처리 보기 전환 시 후보 좌표는 그대로이며, 분석 자체를 바꾸려면 다시 분석해야 한다.
- 전처리 사용 시 PDF 내장 텍스트는 OCR 결과와 섞지 않는다. 원시 PDF 텍스트는 JSON의 `nativeLines`에 별도로 기록한다. OCR 실패를 내장 텍스트로 조용히 대체하지 않는다.
- JSON에 알고리즘 버전, 제외 대상 주석 수, 변경 픽셀 수·비율을 기록한다. 이 비율은 낙서 제거 성공률이 아니다.

손글씨 제거 AI 모델이나 외부 API는 추가하지 않았다. 기존 요청대로 이번 변경도 PDF 실행·브라우저 테스트·타입 검사·빌드 검증은 수행하지 않았다.

## v3: 프롬프트 규칙의 로컬 알고리즘 적용

잘못 추가했던 `/lab` AI 페이지, `/api/lab/regions`, vision 모듈과 API 환경 예시는 제거했다. 사용 경로는 `/lab/pdf-regions`이며 외부 모델/API를 호출하지 않는다. Tesseract 로컬 OCR은 그대로 사용한다.

전처리 이미지에서 이진화 → 작은 획 간격 연결 → 연결 요소 추출을 수행한다. 긴 얇은 단 구분선/페이지 테두리는 제외 대상으로 삼고 짧은 분수선·그래프 축은 일괄 제거하지 않는다. 문항별 OCR 연결 범위에 겹치는 획과 가까운 참조 시각 요소를 포함해 최종 영역을 보완한다. 다른 문항 시작점/영역과 충돌하는 연결은 제외한다.

번호, 본문, 도입부, 질문, 소문항, 선택지, 배점 규칙을 결합한다. (1)(2)는 상위 문항의 연결 범위에 유지한다. 명시적 서술형 섹션 전환에서 전체 번호 offset을 적용하되 원문 번호를 별도 보존한다. 동일 원문 번호와 명시적 '계속/이어서'가 있는 조각만 동일 questionId와 partIndex로 연결한다. 그 밖의 페이지 연결은 미확정 후보다.

JSON에 regions 좌표, questionId/questionNumber/originalNumber/section/partIndex, issues를 추가했다. 필기 분류기가 없으므로 hasHandwriting은 null이다. visualCandidate는 획 크기/연결의 영상 후보이며 이미지/표/수식 의미 분류가 아니므로 hasVisual=false를 임의로 반환하지 않는다. 경계 직접 조절을 제공한다.

이 규칙이 프롬프트의 모든 의미 판단을 구현한 것은 아니다. 겹친 필기, OCR 누락, 획이 이어진 낙서, 복잡한 다단과 긴 자료 연결은 실패할 수 있다. 실행·타입 검사·빌드·브라우저 검증은 사용자 지시에 따라 실행하지 않았다.

## 첫 1쪽 분포 실험

PDF 전체 대신 첫 페이지만 렌더링한다. 기본 `빠른 분포 실험` 모드에서는 OCR 워커를 생성하지 않고 낙서 전처리 → 이진화 → 연결된 획 중심점 추출만 수행한다. 기존 문항 OCR을 비교하려면 빠른 모드를 끄고 다시 분석한다. 이 경우에도 첫 1쪽만 처리한다.

`findInkRegions(..., false)`는 글자 사이를 팽창 연결하지 않은 획 덩어리를 반환한다. 점 하나는 연결 요소의 bbox 중심이다. 한글 자소가 여러 점이 되거나 붙어 있는 글자가 한 점이 될 수 있다. 그림/남은 낙서도 점으로 나온다.

`point-clusters.ts`는 너비 1200px 기준, 종횡비를 유지한 좌표에서 유클리드 거리 이내 점 쌍을 공간 격자로 찾고 union-find로 연결한다. 최소 점 수 미만의 작은 군집은 회색이다. DBSCAN의 핵심점 밀도 기준을 적용한 것은 아니며, 단순 거리 연결 군집이다. 연쇄 연결로 멀리 있는 두 점도 같은 군집이 될 수 있다.

산점도에서 거리(4~100px), 최소 점 수, 전처리 배경, 군집 bbox를 조절한다. 거리 변경은 OCR/전처리를 다시 하지 않고 메모리의 점으로 재계산한다. JSON 다운로드에 점 좌표, 군집 ID, bbox와 거리 설정을 기록한다. bbox는 문항이라고 확정하지 않는다.

사용자 요청에 따라 실행 검증은 하지 않았다.

## OCR + 분포 군집 병행 (기본 모드)

기본 모드는 첫 1쪽 낙서 전처리 후 OCR과 획 분포를 모두 계산한다. 분포만 보기는 선택 기능으로 남겼다. `hybrid-regions.ts`가 OCR의 문항 소속/번호를 기준으로 단과 다음 문항 시작 경계를 구성하고, 각 문항 탐색 범위 안에서 `clusterPoints`를 따로 호출한다. 거리값은 OCR 줄 높이로 정하며 1200px 너비 기준 10~26px에 제한한다.

OCR에 소속된 글자와 겹치는 군집, 명시적으로 참조되고 가까이 있는 시각 요소를 문항에 붙인다. 연결된 군집이 본문 아래로 길게 이어져도 전체 박스를 그대로 사용하지 않고 구성 획 단위로 끝 경계를 검사한다. 다음 번호나 단을 넘어가는 획은 제외하고 확인 안내를 남긴다. 번호를 못 찾은 덩어리는 문항 목록에 임의 번호로 올리지 않으며 진단 정보와 원본/글자 목록에 남긴다.

큰 연결 요소 중 페이지 폭·높이를 넓게 차지하면서 획이 bbox 테두리에 집중된 경우를 외곽 테두리로 제외한다. 이는 일반적인 영상 휴리스틱이며 인쇄된 큰 자료 상자도 오판할 수 있으므로 원본을 보존한다.

UI의 후보 표기를 문항 영역으로 변경했다. 불확실성은 '확인 필요' 안내로 남긴다. 분포 차트는 접힌 상세 영역으로 이동했다. 문항명 변경은 정확도 보증이 아니다. 실제 파일 실행/브라우저/타입/빌드 검증은 수행하지 않았다.

## 단별 분포 우선으로 수정

사용자 스크린샷에서 상단 1번과 3번이 하나의 3번 박스로 합쳐지고 4번 첫 줄만 출력되는 현상을 확인했다. 기존 combineRegions는 OCR 구조 결과에 포함된 그룹만 순회하고 원래 OCR bbox를 항상 최종 rect에 포함했다. 따라서 분포만으로 새 문항을 만들 수 없었으며 이미 양 단을 가로지른 박스를 교정하지 못했다.

수정 후에는 이미지 세로선으로 얻은 단 구역을 먼저 사용한다. 이 구역은 OCR 결과를 받기 전에 정하며 실제 이미지에서 추정한다. 전체 페이지 OCR 결과는 보존하고, 단별 AUTO OCR을 보완 실행하여 빠진 번호와 본문을 다시 읽는다. 단을 가로지른 OCR 줄은 문항 영역 구성에서 제외한다.

각 단 전체에서 독립적으로 거리 군집을 생성하고 OCR 번호·배점·선택지로 군집의 시작/끝과 소속을 결정한다. OCR에 번호가 없어도 충분한 내용이 있는 군집은 '번호 확인' 영역으로 표시한다. OCR 인식 실패를 네 문항인 것으로 추정하거나 번호를 임의 생성하지 않는다. 첫 페이지의 단 수·문항 위치·1~4번을 하드코딩하지 않았다.

원본/분포 시각화/글자 목록을 유지한다. 분포 영역에는 필기나 자료가 섞일 수 있고 단 구분선 없는 복잡한 레이아웃은 여전히 불확실하다. 실제 OCR 중간 결과의 원인별 측정 및 변경 후 동작은 사용자 요청에 따라 실행하지 않았다.

## 전체 페이지 처리

첫 1쪽 제한을 제거하고 업로드한 PDF의 `numPages` 전체를 순차 처리한다. 페이지마다 같은 낙서 전처리·전체/단별 OCR·분포 군집을 적용하며 OCR 워커는 재사용한다. 기존 누적 픽셀 한도 때문에 중간에 중단되는 제한도 제거했다. 파일당 50MB 제한은 유지한다. 페이지가 많으면 브라우저 메모리 사용과 처리 시간이 증가하며 취소 버튼을 사용할 수 있다.

페이지 이동은 분포 전용 모드에서도 표시한다. 분포 제목·접근성 이름·JSON 페이지 인덱스와 파일명이 실제 선택 페이지를 반영한다. 문항 영역/분포의 페이지 좌표는 각 페이지 기준으로 유지한다. 실행 검증은 하지 않았다.

## 번호 검증 강화

`question-number.ts`에서 최종 영역의 문항 시작 번호를 판정한다. 0/앞자리 0(062 등), 소수 표기, 괄호 소문항·원형 선택지, 본문 근거 없는 단독 숫자는 자동 번호로 채택하지 않는다. 전각 숫자는 반각으로 정규화한다. 구분 기호가 없는 숫자는 앞뒤 번호가 모두 뒷받침해야 한다.

같은 단에서 반복되는 번호 위치의 가장 큰 정렬 묶음, 행 높이, 번호 뒤 같은 행 본문, 다음 행 근접 본문, 앞뒤 번호 연속성을 조합한다. 앞뒤 번호와 순서가 충돌하거나 가까운 앞 문항에서 크게 도약하면 보류한다. 같은 물리 위치의 OCR 결과 중 더 많은 근거가 있는 결과를 우선한다. 이 점수는 정답 확률이 아니다.

거절된 번호는 특정 번호로 고쳐 쓰지 않는다. 원시 OCR과 판정 이유를 JSON/화면 '번호 판정 근거'에 유지한다. 독립 군집 표시 경로는 남아 있으므로 내용 자체를 번호 오인식 때문에 삭제하지 않는다. 실제 PDF 실행·테스트·타입·빌드 검증은 수행하지 않았다.


## 2차 형태 필터 (2026-09-21, 미검증 실험)

`shape-ink-filter.ts / suppressIsolatedInk`를 `/lab/pdf-regions`에만 연결했다. UI의 `2차 형태 필터`는 기본 켜짐이며, 색상 전처리와 OCR을 사용하는 경우에만 실행한다. 끄고 재분석하면 기존 경로로 비교할 수 있다. 일반 문제 등록·저장 경로는 변경하지 않았다.

처리 순서: 주석 제외/색상 제거 → 기존 전체·단별 OCR → 형태 필터 → 잉크 분포 재추출 → 기존 문항 번호/경계 계산. 추가 OCR이나 외부 API, 모델 다운로드는 없다. 2차 이미지로 OCR을 다시 수행한 것이 아니라 기존 OCR에서 실제로 제외된 잉크 비율이 95% 이상인 줄만 제외한다. 혼합 줄은 보존한다.

페이지에서 신뢰도 80 이상, 한글/영문 8자 이상인 OCR 줄을 중복 제거해 3줄 이상 확보하면 중간 행 높이를 기준으로 사용한다. 인쇄체라는 확정 판정은 아니며 잘 읽히는 필기가 기준에 섞일 수 있다. 기준 부족 시 전부 유지한다. 거리 군집(최소 점 5개)별 높이 사분위 비율, 큰/가로로 긴 획 비율, 가까운 획의 하단 정렬을 측정한다. 높이 편차 2.2 이상·불규칙 비율 25% 이상·정렬 비율 35% 이하를 동시에 요구한다. 임계값은 실험 가정이며 보정/성능 측정하지 않았다. 150점 초과 군집은 정렬의 제곱 시간 계산을 생략하고 유지한다.

신뢰도 65 이상 OCR, 한글 본문·수식 기호·선택지 등과 가까운 군집, 큰 군집, 긴 획/표/그림 가능성이 있는 연결 요소 주변은 유지한다. 따라서 잘 읽히는 손글씨 수식도 남을 수 있다. 그림 보호는 완전한 검출기가 아니며 작은 도형·OCR에 실패한 수식은 오제거 위험이 있다. 색상 1차 처리 자체의 인쇄물 손상 가능성도 그대로 남는다.

통과 군집 안에서도 원래 해상도의 8방향 연결 잉크 픽셀만 흰색으로 바꾸며 사각형 전체를 지우지 않는다. 군집 경계에 닿는 연결 요소는 보존한다. 팽창·인페인팅·가려진 글자 복원은 없다. 모든 좌표는 같은 렌더 이미지 기준 0..1이며 좌표/회전 변환을 추가하지 않는다.

`colorAsset`(1차), `analysisAsset`(2차), `shapeMaskAsset`(실제 변경 픽셀의 투명 PNG)을 분리 보존하고 `ShapeInkReview`에서 세 단계 비교를 제공한다. 원본 PDF/이미지를 수정하거나 저장하지 않는다. `shapeReport`의 유지/제외 이유·측정값·변경 픽셀 수와 `beforeShapeLines`를 분석 JSON에 포함한다. 미처리 고립점/작은 군집도 남으며 결과 0개는 필기가 없다는 뜻이 아니다.

사용자가 직접 시험한다는 기존 요청에 따라 PDF·브라우저 실행, 테스트, 타입 검사, 빌드는 수행하지 않았다. 변경 파일 포맷팅과 코드 검토만 수행했다.
