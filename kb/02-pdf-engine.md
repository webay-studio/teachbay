# PDF·OCR 엔진 세션 기록

## 목적과 원칙

전체 문제를 텍스트·LaTeX로 복원하는 것보다 원본 영역을 보존하고 문항·지문 관계를 확보하는 것이 목표다. 외부 생성형 AI 없이 PDF 구조, Tesseract OCR, 영상·기하 규칙을 결합하는 방향으로 진행했다. Tesseract 자체는 학습된 인식 모델을 사용하므로 ‘AI가 전혀 없다’와 ‘외부 생성형 AI API를 사용하지 않는다’를 구분한다.

사용자는 반복해서 기존 엔진 정확도를 보존하고 불필요한 알고리즘 변경을 하지 말 것을 요청했다. OCR 정확도 100%라는 사용자 소감은 있었으나 범용 성능 수치로 검증된 것은 아니다.

## 현재 코드 조회에서 확인한 실행 순서

주 진입점: `lib/pdf-region-engine/analyze-pdf.ts`의 `analyzePdf()`.
등록 어댑터: `lib/documents/pdf-registration.ts`의 `importPdfQuestions()`.
아래는 세션 중 마지막으로 엔진 소스를 직접 조회한 시점의 내용이다.

2026-09-23 UI 후속 변경: `PdfAnalysisOptions.onPageRendered({ index, asset })`를 추가해 기존 원본 렌더링 Blob을 등록 화면에 전달한다. 원본 렌더링 이후 문제 영역 분석 진행 메시지도 전달한다. 추가 OCR·분할·잠정 bbox 계산은 실행하지 않으며 최종 구조·문항 소속 계산은 기존 순서 그대로다. 한글 importer는 기존 페이지 분석 완료 시 원본 미리보기를 전달한다.

같은 날 진행 안내 확장: `ImportProgress.stage`로 PDF의 실제 작업 종류를 UI에 알린다. recognize의 전체/부분 영역, AUTO/SPARSE_TEXT, 고해상도 및 숫자 전용 여부를 구분하고 worker 준비·캐시 재사용·형태 분류·문서 연결도 보고한다. OCR 순서·횟수·임계값·캐시 키·결과 구조는 바꾸지 않는다. HWP/HWPX는 아직 stage 세분화 없이 기존 메시지 기반 안내를 사용한다.

1. PDF 형식·50MB 제한 확인 후 PDF.js로 문서를 연다.
2. 페이지를 순차 처리한다. 회전·crop 정보를 반영해 렌더링하고 원본 이미지를 보존한다. 배율은 최대 2.5, 너비 2200·높이 3200을 고려한다.
3. `removeInk`가 켜져 있으면 별도 PDF 주석을 제외하여 재렌더링하고 `suppressColoredInk()`로 특정 빨강·파랑 픽셀을 흰색 처리한다. 검정 필기를 모두 지우는 알고리즘은 아니다. 인쇄 색상도 영향을 받을 수 있다.
4. `physicalRegions()`로 단/읽기 구역 후보, `findInkRegions()`로 연결 성분을 구한다. 기본 연결성은 4방향이다.
5. PDF 네이티브 텍스트를 추출해 `nativeObservation()` 및 `assessNativeFonts()`로 글꼴·원본 잉크·좌표 대응을 평가한다. `joinLines()`로 글줄을 구성한다.
6. PDF 연산자에서 이미지 컨테이너·벡터 기하·가로선 정보를 확보한다. 그림은 OCR 문자열만으로 처리하지 않는다.
7. 구역별 네이티브 근거를 평가해 native/scan/mixed로 구분한다. 충분히 깨끗한 텍스트 영역은 OCR을 생략할 수 있다.
8. 필요한 OCR을 실행하고 단어·줄 bbox, source, passId, transform, confidence를 보존한다.
9. 색상 처리 및 shapeFilter가 켜져 있으면 `suppressIsolatedInk(..., false)`로 형태 분류를 수행한다. 현재 호출은 비파괴 분류이며 2차 필터가 픽셀을 삭제한다고 설명하지 않는다.
10. 색상 제거와 신뢰 가능한 네이티브 인쇄 글자가 충돌하면 원본에서 잉크 기하를 다시 구해 보존한다.
11. 모든 페이지 관측으로 `buildStructure()` → `combineRegions()` → `assignDocumentOwnership()`를 실행한다.
12. 등록 어댑터가 문항 조각·공통 자료·이미지 자산·원본 문서를 등록 데이터로 변환한다. 2026-09-23: `autoBundlePassages`가 기존 materialIds로 초기 저장 묶음 설정(PDF/한글 import); OCR/소속 계산·bbox 변경 없음.

## OCR 순서와 비용

등록 화면은 조회 당시 `ocrPolicy: "legacy"`를 명시했다. `adaptive` 분기도 있지만 기본 등록 경로는 아니었다.

- 모든 단의 네이티브 텍스트가 충분하면 기본 OCR 생략.
- 부족하면 페이지 전체 AUTO 1회.
- 전체 SPARSE_TEXT 1회.
- 다단이면 감지된 각 단 AUTO.
- 번호 없음/불연속인 구역 중 최대 2개에 SPARSE_TEXT 추가.
- `numberRetryCrops()`가 만든 시작 줄 후보 최대 8개를 원본에서 2배 배율로 재렌더링해 SINGLE_BLOCK 인식.
- 조건에 맞는 헤더 페이지 번호 후보가 있으면 숫자 전용 고해상도 인식 1회 추가.

일반적인 2단에서 조건부 최대 14회, 헤더 재인식까지 15회가 될 수 있다. 항상 전부 실행되는 것은 아니다. 시작 줄 재인식은 확실히 실패한 번호만 대상으로 하지 않는다.

`ocr-result-cache.ts`는 픽셀·크기·분할 모드·숫자 전용 여부에 기반한 제한된 탭 메모리 캐시다. 캐시 조회 횟수와 실제 인식 횟수는 다르다. OCR worker는 `ocr-worker.ts`에서 재사용한다. 결과 캐시와 언어 모델 파일 캐시는 별개다.

## 구조·번호·영역

- `structure.ts`: 분리된 번호/본문 합치기, 중복 관측 정리, 반복 머리말·꼬리말 등 글줄 역할 판정.
- `question-number.ts`: 번호 표기, 왼쪽 정렬, 글자 높이, 본문, 인식 신뢰도 등의 근거로 번호 검증. 같은 위치의 여러 OCR 패스를 독립된 투표로 계산하지 않는다.
- `hybrid-regions.ts`: flow region 순서, 번호 앵커, 글줄·수식·그림 등의 블록으로 문항 구성.
- `document-ownership.ts`: 공통 자료, 문항 소속 및 의존 관계 정리.
- `ocr-retries.ts`: 고해상도 부분 재인식 후보 생성.

‘다음 번호까지 사각형을 채운다’만으로 저장 범위를 만들지 않는다. 넓은 후보 구역과 실제 콘텐츠 영역을 구분하고 풀이 여백·필기를 자동으로 인쇄물과 완벽히 구분한다고 주장하지 않는다.

## 보존해야 할 모델

- Fragment/QuestionPart: 원본 문서·페이지·좌표·좌표 변환·읽기 순서·원본 참조. 문항 하나에 여러 조각 가능.
- Question: 내부 ID, 원본 번호/표기, 섹션, 순서 있는 parts, 공통 자료 참조, 상하위/의존 관계, 확인 상태와 사유.
- SharedMaterial: 지문·표·보기·조건 등의 독립 자료. 여러 페이지 조각 및 여러 문항의 참조 허용.
- 관계: 이어짐, 문항 소속, 선택지 소속, 공통 자료 필요, 하위 문항, 다른 문항 의존.
- 원본 번호만으로 ID를 만들지 않는다. 섹션 번호 재시작과 전체 표시 번호를 구분한다.
- 불확실한 연결은 후보/확인 필요로 남긴다. 누락 내용을 생성하지 않는다.

## 사용자가 제공한 회귀 지시서의 중요 사례

아래는 사용자 제공 검토 보고서의 내용이며, 본 세션에서 전체 정답 박스를 다시 라벨링한 결과가 아니다.

- `1111.pdf`: 22개 논리 문항, 24개 물리 조각을 기대. 14번은 2쪽 왼쪽 하단→오른쪽 상단. 18번은 2쪽 번호만→3쪽 본문·선택지.
- `1111.pdf`, `2222.pdf`: 네이티브 번호 1~22가 각 한 번 확인됐다는 보고. 이는 bbox 정확도 100%를 뜻하지 않는다.
- 두 디지털 PDF의 5번: 본문 도형 1개와 2열·3행 선택지 도형 5개 보존 필요.
- `2222.pdf`: 넓은 풀이 여백 제외, 마지막 페이지 빈 오른쪽 단에서 가짜 문항 금지.
- 상산고 스캔 18번: 배점 아래 인쇄 도형 존재. 배점을 확정 종료선으로 쓰면 잘린다.
- 상산고 3~4쪽: 조건·수식과 필기 중첩. 필기 삭제와 영역 검출을 분리 평가.
- 상산고 6쪽: 단답형 1~18 이후 서술형 1~4로 번호 재시작.
- 상산고 PDF는 래스터 페이지, 텍스트·주석 0개 및 90/270도 교대 회전이라는 사용자 보고.
- 한국지리: 간헐적 왼쪽 단 누락을 논의. 20번 하단 안내 상자 포함은 기존 한계로 기록됐다.

## 평가 원칙과 미검증 범위

문항 수뿐 아니라 미탐·오탐·병합·분할·본문/수식/그림/선택지 보존·공통 자료 연결·순서·인쇄 오삭제·사용자 수정 시간을 평가한다. bbox IoU만으로 성공을 선언하지 않는다. 새로운 출처/레이아웃을 분리해 검증한다.

장문 국어·영어 지문, 3단, 중간 단 변화, 컬러 인쇄, 누락 페이지 등에 대한 범용 성능은 확정하지 않았다. 서버 이전, Supabase 비용, OCR 텍스트화·수식 인식, 유료 품질 개선은 논의했지만 서버 구현이나 비용 측정 완료로 기록하지 않는다.
