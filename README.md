> 현재 제품명은 **teachbay**입니다. 샘플 생성·데모 배지·예시 시험지 UI는 제거했습니다. 시작 화면은 회원가입 없이 브라우저 작업 공간을 여는 방식이며 서버 인증은 아직 없습니다. 아래 과거 검증 기록의 샘플·데모 내용은 당시 기준입니다. 기존 저장 자료 보존을 위해 IndexedDB 이름과 세션 키는 유지합니다.

# teachbay

개인 강사가 문제 이미지를 모아 시험지를 만들고 다시 출력하는 실행 가능한 프런트엔드 초안입니다. Next.js App Router, React, TypeScript, Tailwind CSS를 사용합니다. 서버 인증이나 원격 저장소는 없습니다.

## 실행

Node.js 22.13 이상이 필요합니다. 검증 환경은 Node.js 24.3입니다.

```sh
npm install
npm run dev
```

터미널에 표시된 주소를 여세요. 기본 포트는 3000이며 다른 서비스가 사용 중이면 Next.js가 다른 포트를 선택합니다. `/login`에서 **데모로 시작하기**를 누르세요. **샘플 문제 넣기**는 사용자가 명시적으로 실행할 때만 직접 제작한 이미지 6장을 저장합니다.

```sh
npm run typecheck
npm test
npm run format:check
npm run build
npm start
```

이 저장소에는 초기 코드나 기존 린트 명령이 없었습니다. 타입 검사, 의미 있는 단위 테스트, Prettier 검사, 프로덕션 빌드를 제공하며 ESLint는 별도로 설정하지 않았습니다.

## 구현된 화면

- `/login`: 데모 로그인과 지속되는 로그인 상태. 비밀번호 입력·저장 없음.
- `/questions`: 이미지 카드, 전체/개별 선택, 이름·파일명·메모 검색, 이미지 확대, 이름·메모 수정, 확인 후 삭제. 검색과 별개로 선택 유지.
- `/questions/new`: PDF/HWP/HWPX 문서 자동 분리와 검토, JPG/PNG/WebP 다중 파일 선택·드롭·이미지 붙여넣기, 20MB 한도, 미리보기, 개별 제외, 선택적인 이름·메모, 비율을 고정하지 않는 사각형 자르기. 입력창의 일반 붙여넣기는 그대로 유지.
- `/exams/new`: 드래그 및 위/아래 버튼으로 순서 변경, 문항 추가·제외, 제목·1/2단·풀이 공간 실시간 변경, 번호·이름란·날짜·로고 세부 설정, 초안 자동 저장, 저장 및 저장 후 인쇄 요청.
- `/exams`: 제목 검색, 최신순 보관함, 미리보기, 다시 출력, 복사해서 수정, 확인 후 삭제.
- `/exams/[id]`: 저장 당시 제목·문항·순서·설정으로 재열기와 출력. 재출력만으로 기록이 추가되지 않음.

제작·편집·출력은 모두 무료이며 워터마크나 출력 제한이 없습니다. 유료 기능, AI 타이핑, 학원 관리 기능은 포함하지 않았습니다.

## 구조와 저장

| 파일 | 역할 |
| --- | --- |
| `lib/types.ts` | Question, ImageAsset, Exam, ExamDraft, 출력 설정 |
| `lib/db.ts` | IndexedDB 데이터 접근, 문제+이미지 원자적 일괄 저장 |
| `lib/auth.ts` | 데모 인증 어댑터. 실제 인증 공급자를 연결할 위치 |
| `lib/images.ts` | 이미지 검증, 크기 확인, 명시적으로 생성하는 샘플 |
| `lib/layout.ts` | mm 단위 A4 배치 및 페이지 분할 |
| `lib/print.ts` | 폰트·이미지 DOM 준비·decode·레이아웃 프레임을 기다린 후 브라우저 출력 요청 |
| `components/shared.tsx` | 공통 내비게이션, 이미지 URL 수명 관리, 확대/편집 모달 |
| `components/cropper.tsx` | 포인터 선택 및 키보드 범위 조절, 원본 해상도 Canvas 자르기 |
| `src/screens/editor/EditorScreen.tsx` | 시험지 제작 화면 조립 (`_handler`에서 초안 자동 저장 조율) |
| `components/exam-renderer.tsx` | 미리보기·인쇄 공용 시험지 렌더러 |
| `app/globals.css` | 반응형 화면 및 별도 인쇄 스타일 |

IndexedDB `teachway` (버전 2)에 `documents`, `questions`, `assets`, `exams`, `drafts` 스토어를 둡니다. `assets`는 원본 이미지 Blob, MIME, 원본 너비·높이를 저장합니다. Base64 이미지를 localStorage에 넣지 않습니다. localStorage에는 `teachway-demo` 로그인 플래그만 저장합니다.

시험지는 정렬된 문항 스냅샷과 출력 설정을 보존하고 별도 이미지 자산을 참조합니다. 원본 문제의 이름 수정이나 삭제가 시험지에 전파되지 않습니다. 같은 초안을 변경 없이 다시 저장·출력할 때도 저장된 ID를 재사용합니다. 복사본은 새 초안으로 시작하고 새로운 시험지 ID로 저장됩니다.

이미지 보존을 우선해 현재는 문제·시험지 삭제 시 Blob을 자동 수거하지 않습니다. 따라서 장기간 사용하면 참조되지 않는 이미지도 공간을 차지할 수 있습니다. 추후 서버 저장을 연결할 때 참조 검사 기반 자산 정리를 추가할 수 있습니다.

실제 서버로 전환할 때 `lib/db.ts`의 비동기 CRUD와 일괄 저장을 API 호출로 교체하고, `lib/auth.ts`와 `Shell`의 세션 확인을 실제 인증으로 연결하세요. 접근 제어는 서버에서 별도로 구현해야 합니다.

## 출력 동작

A4 세로 210×297mm, 가로 여백 16mm, 단 간격 10mm, 공통 본문 높이 239mm입니다. 이미지 원본 비율로 필요한 높이와 풀이 여백을 계산해 한 문제를 통째로 다음 단·페이지에 배치합니다. 한 문제 자체가 너무 길면 비율을 유지해 축소하고 65% 미만 축소 시 알립니다.

미리보기와 인쇄는 같은 페이지 배열과 DOM을 사용합니다. 인쇄 스타일에서는 내비게이션, 편집 UI, 안내, 개발 도구를 제외합니다. 브라우저 인쇄 창에서 A4, 배율 100%를 확인하고 프린터 또는 PDF 저장을 선택하세요. 출력 창을 요청했다는 사실을 인쇄 완료로 표시하지 않습니다. 인쇄 취소 여부와 관계없이 먼저 저장한 시험지는 남습니다.

- 검색 결과 없음, 검색어 변경 시 선택 유지.
- 로그아웃 → 재로그인 후 자료 유지.

확인하지 못한 항목:

- Chrome 확장의 로컬 파일 접근 권한 때문에 파일 선택을 통한 실제 업로드 자동 검증은 차단되었습니다. 이미지 드롭·클립보드 붙여넣기·자르기·오류 파일 혼합 업로드도 수동 확인이 필요합니다.
- 컴퓨터 제어 권한이 없어 OS/브라우저 인쇄 창 내부와 실제 PDF 결과, 실제 프린터 출력은 확인하지 못했습니다. 출력 요청과 저장 기록, 동일 렌더러, 레이아웃 계산은 확인했습니다.
- 브라우저 저장 공간 부족은 실제로 강제 재현하지 않았습니다. 저장 오류/트랜잭션 중단과 QuotaExceededError의 한국어 안내가 구현되어 있습니다.
- 원본 삭제 후 보존은 fake-indexeddb 자동 테스트로 확인했으며 실제 브라우저 삭제까지 반복하지 않았습니다.
- 개발 모드에서는 설치된 HWP 브라우저 확장이 `<html>` 속성을 추가해 외부 확장으로 인한 hydration 경고가 관찰되었습니다.

## 데모의 제한

자료는 현재 브라우저의 해당 origin(프로토콜·호스트·포트)에만 저장됩니다. 다른 포트나 브라우저에서는 다른 보관함입니다. 브라우저 데이터 삭제, 사생활 보호 모드 종료, 저장소 정리 등으로 자료가 사라질 수 있습니다. 서버 백업, 기기 간 동기화, 보안 인증은 구현하지 않았습니다. 로그아웃 자체로 문제나 시험지를 삭제하지 않습니다.


## PDF · HWP · HWPX 자동 분리 (추가 구현)

문제 등록 화면에 문서를 올리면 원본 페이지를 렌더링한 뒤 문제 번호, 글자 좌표, 단 구성을 이용해 영역을 제안합니다. 공통 지문과 각 문항은 **서로 다른 항목으로 저장**합니다. `[1~3]` 같은 번호 범위가 있으면 같은 세트의 출처 정보를 함께 남깁니다.

- **PDF**: PDF.js로 페이지를 고해상도 렌더링하고 텍스트 좌표를 추출합니다. 본문 텍스트가 부족한 스캔 페이지는 Tesseract.js 한글·영문 OCR을 실행합니다.
- **HWP/HWPX**: `@rhwp/core` WebAssembly 렌더러로 페이지와 텍스트 좌표를 추출합니다. 글꼴·수식·표 호환성은 원본 한글 프로그램과 다를 수 있어 검토 안내를 표시합니다. 외부 링크·스크립트가 있는 SVG는 표시 전에 제거합니다.
- **다음 단/쪽으로 이어지는 문항**: 읽기 순서(왼쪽 단 → 오른쪽 단 → 다음 쪽)에서 다음 문항 번호 전의 내용을 이전 항목에 이어 붙인 후보로 제시합니다. 여러 영역은 개별 조각과 읽기 순서를 유지해 저장합니다. 긴 공통 지문도 동일하게 연결됩니다.
- **분리 검토**: 원본 영역 오버레이, 종류/이름 변경, 단 구성 재분석, 여러 후보 합치기, 한 영역을 둘로 나누기, 이어진 영역 각각 분리, 다른 페이지의 영역 추가, 드래그/키보드 범위 수정, 제외, 되돌리기를 제공합니다. 검토 내용을 닫았다 다시 열어도 현재 등록 화면 안에서는 유지합니다.
- **저장**: 원본 비교 확인 후 등록 목록에 추가하고 기존 저장 버튼으로 IndexedDB에 저장합니다. 아직 검토하지 않은 문서가 남으면 저장을 막아 조용히 누락시키지 않습니다. 원본 문서 Blob, 페이지와 좌표 변환, 승인된 영역 PNG Blob, 문항·공통 지문 연결을 IndexedDB에 함께 저장합니다.
- **실패/취소**: 파일당 50MB/40쪽 제한, 암호 PDF 안내, 문서 파싱 오류, OCR 실패 시 원본 페이지 보존, 작업 진행률 및 취소를 처리합니다. OCR 작업이 미완료 상태여도 취소가 해제되도록 별도 AbortSignal 경쟁 처리를 합니다. 한 파일의 오류가 이미 처리한 다른 파일을 지우지 않습니다.

자동 인식은 완벽한 의미 분석이 아닌 **규칙·좌표·OCR 기반 후보 생성**입니다. 번호 없는 문항, 선택지의 숫자, 혼합 단, 사진·복잡한 표, OCR 오인식에서는 분리/연결이 틀릴 수 있습니다. 다음 페이지의 앞부분을 항상 이전 문제로 확정하지 않고 연결 후보임을 표시하며 저장 전에 사람이 검토합니다. 실패한 페이지는 버리지 않고 수동 영역 지정 대상으로 남깁니다. 장기간·다양한 실제 문제집의 분리 정확도는 아직 검증하지 않았습니다.

한 번에 붙인 이미지가 30,000px 또는 45MP를 넘으면 나누어 저장하도록 안내합니다. 문서 등록 도중 새로고침하면 아직 저장하지 않은 분석/검토 내용은 사라집니다. 저장 후에는 기존과 동일하게 새로고침해도 유지됩니다.

### 문서 처리 파일

| 파일 | 역할 |
| --- | --- |
| `lib/documents/import.ts` | PDF/HWP/HWPX 렌더링, 텍스트 좌표 추출, OCR, 오류/취소 |
| `lib/documents/segment.ts` | 단 감지, 번호/지문 경계, 페이지·단 연결, 수동 합치기/분리 |
| `lib/documents/compose.ts` | 승인된 영역을 고해상도 이미지로 합성, 바깥쪽 빈 행 정리 |
| `lib/documents/cancel.ts` | OCR 작업 취소 시 대기 중인 Promise 해제 |
| `components/documents/document-review.tsx` | 원본과 후보를 비교하는 검토 화면 |
| `scripts/prepare-document-assets.mjs` | 라이브러리 worker/WASM/언어 모델을 앱에서 제공하도록 복사 |

`npm install`의 postinstall이 `public/document-runtime/`에 약 70MB의 런타임을 준비합니다. 해당 생성 디렉터리는 Git에서 제외하며 `npm run prepare:documents`로 다시 만들 수 있습니다. 배포 시 이 디렉터리도 정적 파일로 제공해야 합니다. 브라우저는 필요한 worker/모델만 지연 로딩합니다. OCR 모델·PDF worker·HWP WASM은 앱의 동일 origin에서 가져오고 문서 자체는 외부 OCR 서버에 전송하지 않습니다.

사용한 라이브러리의 공식 문서: [PDF.js](https://mozilla.github.io/pdf.js/examples/), [Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md), [RHWP](https://github.com/edwardkim/rhwp). 패키지 라이선스 사본도 런타임 디렉터리에 복사합니다.

### 추가 검증

- TypeScript 검사 통과.
- 전체 테스트 15개 통과: 기존 5개 + 문항/지문 번호, 분리된 텍스트 조각 합치기, 단 감지, 공통 지문 세트, 페이지/단 연결, 원본 보존, 수동 합치기/나누기, 반복 머리말/쪽번호 처리, OCR 취소.
- 실제 Chrome에서 샘플 PDF 2쪽 → 지문 1개 + 문제 6개, 다음 단/쪽에 걸친 문제 각각 2개 영역으로 연결 확인.
- 실제 스캔 PDF → OCR로 문항 2개 생성 확인.
- 실제 HWP 및 HWPX 파일 바이트 생성 → 파싱/렌더링 → 지문 1개 + 문제 3개 확인. HWPX 검토 화면에서 나누기/합치기 → 등록용 PNG 4개 생성 확인.
- 운영 의존성 보안 검사: 알려진 취약점 0건.
- 다양한 실제 한글 문서의 수식/표/글꼴 정확도, 복잡한 문제집의 자동 분리 정확도는 미검증입니다. 예전 검증 제한에 적은 Chrome 파일 선택기 권한은 그대로이므로 샘플 버튼을 통해 동일한 File 가져오기 경로를 검증했습니다.

추가 기능의 프로덕션 빌드도 통과했습니다. 실행 중인 등록·검토 화면을 건드리지 않도록 동일 소스의 임시 복사본에서 빌드했습니다.

## 원본 보존형 등록 엔진 실험

[상세 설계](docs/registration-engine-design.md)는 원본 조각·공통 자료·문항 의존 관계, 단계별 판단 규칙, 비용/평가 계획을 설명합니다. 현재 UI의 PDF 가져오기를 대체한 기능은 아니며 독립 프로토타입입니다.

```sh
npm run benchmark:registration -- "/absolute/path/exam.pdf"
npm run benchmark:registration -- "/absolute/path/exam.pdf" --ocr
```

Node 22.13 이상, `npm install` 및 `npm run prepare:documents` 후 실행합니다. 첫 명령은 OCR/AI를 사용하지 않으며 둘째는 설치된 한국어·영어 Tesseract 로컬 모델을 사용합니다. 외부 AI API 호출은 없습니다. `output/registration-baseline/review-no-ai.html` 및 `review-ocr.html`에서 원본과 후보 오버레이를 볼 수 있습니다. 같은 출력 폴더를 덮어쓰므로 서로 다른 파일을 동시에 실행하지 마세요.

원본 PDF를 수정하거나 복제하지 않으며, JSON의 `sourceRef`는 입력 파일의 절대 경로입니다. 이 경로가 이동하면 참조가 깨지므로 제품 저장소용 영구 저장 구현으로 취급하면 안 됩니다. 파생 이미지/텍스트/경로가 포함된 실험 산출물은 `.gitignore`로 제외했습니다. 모든 관계 후보는 검토 필요 상태이며 자동으로 문제 저장소에 등록하지 않습니다.

실제 지정 사례에서 기존 OCR+번호 규칙은 표지 유의사항 오검출과 여러 페이지 과병합을 보였습니다. 상세 실패 기록은 실험 폴더의 `findings.md`를 확인하세요. 원본 번호 검출 개수나 코드 테스트 통과를 분리 정확도로 보고하지 않습니다.

### 2026-09-18: PDF 하단 풀이 영역 포함 오류 수정

넓은 문항 탐색 범위와 실제 저장 범위를 분리했습니다. 본문 끝을 뒷받침하는 OCR 근거가 있을 때 검토 제안을 표시하고, 확인 후 적용할 수 있습니다. 필기 제거 기능은 아니며 불확실한 범위는 원본을 유지합니다. 실제 호출 경로, 동일 PDF 전후 검증 수치, 4번 문항 오분리 등 남은 실패는 [수정 검증 기록](docs/content-bounds-fix.md)을 참고하세요. 로컬 전후 이미지 보고서는 `output/content-bounds/report.html`입니다.

현재 실험 알고리즘은 [`lib/pdf-region-engine`](lib/pdf-region-engine/README.md)에 분리되어 있습니다. 공개 진입점은 `analyzePdf`이며 `/lab/pdf-regions`에서 사용합니다. 모듈 역할, 호출 예시, 저장소 경계와 회귀 검증 방법은 엔진 문서를 참고하세요.


## 등록 페이지 엔진 통합 (2026-09-21)

`/questions/new`의 PDF 분석은 `lib/pdf-region-engine`을 사용합니다. `/question/new`도 같은 화면으로 이동합니다. `/lab/pdf-regions`와 실험 전용 진단 화면은 삭제했습니다. PDF 검토와 이미지 자르기는 모달 없이 등록 페이지 안에서 진행합니다.

문항을 선택하면 필요한 공통 지문도 함께 포함합니다. 선택과 경계 수정은 검토를 접었다 다시 열어도 유지됩니다. 원본과 비교해 확인한 항목만 등록 목록에 추가하고 저장합니다. 문항 분리 알고리즘의 임계값이나 OCR 정책은 이번 통합에서 바꾸지 않았습니다.

연결 파일: `lib/documents/pdf-registration.ts`(엔진→등록 데이터), `components/documents/document-review.tsx`(인라인 검토), `lib/documents/prepare-registration.ts`(원본·조각·관계 저장 준비). HWP/HWPX 경로와 다른 화면의 모달은 유지합니다. 과거 검증 기록은 당시 구현 기준이며 이번 검증은 `docs/registration-integration.md`를 참고하세요.
